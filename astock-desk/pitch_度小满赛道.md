# 躬行 Praxis · 度小满赛道定位说明

> 分支：`duxiaoman-advisor`。这条线**保留原版专业投研外观与逻辑**（暗色终端风格，不做绘本化改造），因为度小满评的是"投顾专业性"而不是"新手友好度"——两个赛道的评审标准根本不同，不能用同一套皮肤应付两场比赛。
> 另一条 `storybook-restyle` 分支（绘本风+可玩性）专供智能少年赛道，两条线正式分开维护。

---

## 1. 赛道原文与本产品的对位关系

度小满赛道要的不是"更智能的问卷"，而是"真正理解用户财务状况、风险偏好、所处生活阶段"的 AI 投顾。核心红线：**产品定位为投顾而非行情软件**，不能只优化 K 线展示或资讯聚合。

躬行 Praxis 现在的形态，恰好精确落在赛道给出的第二个可选方向上：

> **AI理财教练：不直接给出操作答案，通过对话式引导帮助用户搭建属于自身的理财认知框架，养成长期良好理财习惯。**

产品里没有一处告诉用户"买"或"卖"，所有输出都是共识、分歧、待核验问题——这不是营销话术，是写进 `lib/agents.py` 里 `IRON_RULES` 的强约束（见第 3 节）。

## 2. 逐条回答赛道提交问题

**Q1 产品核心服务人群**
18–25 岁、有基础收入但缺乏系统理财训练的新手投资者：他们能自己开户下单，但缺的是"看到一条消息该不该信"的判断框架，而不是缺一个下单入口。

**Q2 目标用户理财痛点及判断依据**
痛点：习惯把"别人说好"当成"我该买"，缺少反证思维和仓位纪律，追涨杀跌是最常见的行为模式。判断依据：产品的核心交互设计本身就是这个痛点的镜像——灵魂三问强制用户在下单前写出证据、反证和纪律，这三项恰好是新手最容易跳过的三步；如果这三步不难答，这个产品也没有存在的必要。

**Q3 AI 投顾的建议生成逻辑**（评审最看重的一条）
分五层递进，任何一层都不落到"买/卖"结论：
1. **数据层**（`lib/market.py`）：多源行情兜底（腾讯/东方财富/新浪），财务、资金流、新闻、K 线指标统一采集。
2. **三视角研判层**（`lib/agents.py: analyst_fundamental/technical/sentiment`）：基本面、技术面、情绪资金面三个独立 LLM 角色并行出具研报，刻意让三者可能互相冲突——现实里没有一个视角能替另外两个说话。
3. **首席研判官层**（`researcher_decide`）：不裁决三份研报谁对，只提炼共识、核心分歧、以及**下单前必须自己回答的一个问题**。这是"投顾"和"荐股软件"的分界线：前者交还判断权，后者替用户下结论。
4. **风控教练层**（`risk_review`）：独立审查仓位建议、追涨迹象、流动性和系统性风险，输出"可继续研究/补充证据/暂缓模拟决策"三态判决和单一持仓上限建议——这是异常场景的核心应对机制。
5. **下单闸门层**（`gate_check`）：模拟下单前，AI 检查用户的灵魂三问回答是否具体、是否包含反证和纪律，笼统回答（如"随便""感觉会涨"）会被打回，给出苏格拉底式追问而不是直接放行。

**风险提示与人工介入机制**：`IRON_RULES` 硬编码在每一个 LLM 调用的系统提示里（不是靠模型自觉），明确禁止给出目标价、买入区间、止损价或收益承诺；风控教练判决为"暂缓模拟决策"时，前端会阻断下单流程，只能返回补充证据。这套约束在提示词层和产品流程层做了双重实现，不是单靠一句免责声明。

**Q4 技术资源组合方案**
- 模型：DeepSeek 主通道（`DEEPSEEK_MODEL_FAST` / `MODEL_STRONG` 分别处理轻量与强推理任务）+ 阶跃星辰自动备用通道与语音复盘（TTS）。
- 数据源：腾讯/东方财富/新浪三源行情兜底，网络全断时降级到显式标注的"课堂模式（快照数据）"，绝不伪装成实时行情。
- 存储：SQLite 本地持久化模拟盘与决策日志，服务端不存用户姓名，浏览器匿名 ID 关联。
- 部署：纯 Python 标准库 HTTP 服务 + Docker，Zeabur 一键部署。

**Q5 项目当前完成度**
已实现：模拟盘（虚拟资金/持仓估值/决策日志）、投研委员会（三视角+首席研判官+风控教练全链路）、多空法庭（红蓝论据找逻辑缺陷）、概念图鉴、复盘信（引用用户原话识别认知偏差）、策略照妖镜（MA/MACD/RSI 历史回测对照买入持有）。
未完成 / 下一步：赛道方向三提到的"多资产跨市场统一管家"目前只做了单标的分析，尚未做跨账户资产聚合；理财决策陪伴助手的"市场波动主动介入"目前是用户主动查询触发，还没做成主动推送。
最大挑战：如何在"教育"和"陪伴"之间不滑向"建议"——每加一个新功能都要先过一遍 IRON_RULES 红线检查，这是比写代码更花时间的部分。

## 3. 评审标准逐项自查

**专业性**——资产配置/风险管理原则体现在风控教练的仓位上限建议和"仓位纪律"话术里，且基本面/技术面/情绪面三分离研判符合真实投研流程，不是单一模型一次输出。

**创新性**——AI 的介入方式是"三个可能互相冲突的视角 + 强制反证 + 下单闸门"，闸门机制会真的拒绝笼统回答并追问，这是"聊天框套壳"做不到的产品化约束，不是提示词包装。

**可信度**——`IRON_RULES` 五条铁律写死在每次 LLM 调用里，紧急场景（风控判决暂缓）会真的阻断下单流程；`README.md` 的"安全边界"章节公开写明数据不做撮合、不能评估实盘执行效果，主动划清能力边界而非夸大。

**可用性**——概念图鉴把术语讲解做成可收藏的教学卡，理财小白遇到不懂的词随点随学；但需要诚实指出：这条分支保留的是专业终端视觉风格，如果评委反馈"小白友好度不够"，团队应参考 `storybook-restyle` 分支里已经验证过的破解思路（三步下单、白话卡片、传唤证人式提示）做针对性移植，而不是整体套用绘本皮肤（那会削弱专业投顾的定位）。

**完整度**——从数据采集到研判到风控到模拟下单到复盘信，五层闭环全部可跑通，本地零第三方 Python 依赖，`python3 server.py` 即可演示。

## 4. 现场演示建议顺序

1. 搜索一支股票 → 召开投研委员会，展示三视角研判**确实会互相打架**（如基本面看多、技术面看空），凸显"不是套壳"。
2. 点开首席研判官的"下单前必须回答的问题"，追问评委：这条问题，普通荐股软件会问吗？
3. 故意在灵魂三问里写"随便，感觉会涨"，展示下单闸门拦截 + 苏格拉底追问。
4. 认真填三问后完成模拟下单，几天后（或用测试账号）展示复盘信如何引用当时原话点出认知偏差。
5. 收尾强调：全程没有一句"建议买入"或目标价——这是产品化的合规，不是一句免责声明。
